ریکال هر چیزی که کپی می‌کنید را به خاطر می‌سپارد تا بتوانید نه فقط با کلمات دقیق، بلکه بر اساس *معنا و مفهوم* آن‌ها را جستجو کنید. علاوه بر این، با اطلاعات حساس مثل رمزهای عبور، مثل مواد رادیواکتیو (با نهایت احتیاط) رفتار می‌کند!

![پنل تاریخچهٔ Recall: جستجوی «rounding» قطعه‌کد border-radius در CSS را پیدا می‌کند، در حالی که این واژه هرگز در آن نیامده](docs/demo.gif)

مثلاً با جستجوی **rounding** (گرد کردن)، کد `border-radius` را پیدا می‌کند؛ بدون اینکه این کلمه اصلاً در متن کپی‌شده وجود داشته باشد. اینجا خبری از لیست مترادف‌ها یا پردازش ابری نیست: همه‌چیز توسط یک مدل embedding محلی و یک ابزار بسط جستجو، مستقیماً روی مک شما اجرا می‌شود.

## چرا یک مدیر کلیپ‌بورد دیگر؟

چون چالش‌های اصلی یک مدیر کلیپ‌بورد، فقط ذخیره کردن و ساختن یک لیست ساده نیستند. مسئله این است که:

* **شما معمولاً *مفهوم* چیزی که کپی کرده‌اید را یادتان می‌آید، نه کلمات دقیقش را.** پس جستجو باید بر اساس معنا کار کند.
* **مدیر کلیپ‌بورد راحت‌ترین جا برای سرقت اطلاعات حساس روی سیستم است.** پس باید طوری طراحی شود که ذاتاً در برابر این موضوع مقاوم باشد و چنین اطلاعاتی را پس بزند.
* **مدل هوش مصنوعی باید همان‌جایی اجرا شود که داده‌ها هستند.** فرستادن کل تاریخچهٔ کلیپ‌بورد به یک سرور خارجی فقط برای گرفتن یک خلاصه از یک جمله، اصلاً منطقی نیست.

تمام ویژگی‌های Recall بر اساس همین سه اصل ساخته شده‌اند.

## جستجویی که واقعاً کار می‌کند

کافیست چیزی که حدس می‌زنید یا نیمه‌کاره یادتان مانده را تایپ کنید. Recall پرس‌وجوی شما را به‌صورت محلی (On-device) پردازش کرده و با تک‌تک آیتم‌ها مقایسه می‌کند. البته برای اینکه با بزرگ شدن تاریخچه سرعت افت نکند، اول یک فیلتر اولیه نتایج را محدود می‌کند تا متد brute force همچنان سریع بماند.

دلیل اینکه مثال بالا (جستجوی rounding) کار می‌کند، بسط معناییِ پرس‌وجوست. اگر فقط از embedding استفاده کنیم، کلمهٔ *«rounding»* ممکن است نسبت به یک دستور نامربوطِ CSS، رتبهٔ پایین‌تری بگیرد. اما اینجا، یک مدل زبانی محلی ابتدا کلمهٔ شما را بسط می‌دهد تا نتایج دقیق‌تری بگیرید. این صرفاً یک ادعا نیست؛ با ابزارهای ارزیابی و تست‌های واقعی (مثل امتیازدهی recall@3) کاملاً سنجیده شده است.

علاوه بر این، می‌توانید جستجوهای خود را با عملگرها ترکیب کنید:

| عملگر | چه چیزی پیدا می‌کند؟ |
| --- | --- |
| `kind:image` | فقط تصاویر (موارد دیگر: `text`، `link`، `color`، `file`) |
| `app:Xcode` | فقط مواردی که از یک برنامهٔ خاص (مثل Xcode) کپی شده‌اند |
| `since:yesterday` | آیتم‌های کپی‌شده از دیروز تا الان |
| `is:pinned` | آیتم‌های پین‌شدهٔ شما |

**کالکشن‌های هوشمند (Smart Collections)** جستجوهایی هستند که ذخیره می‌شوند. این کالکشن‌ها به‌صورت خودکار با تگ‌ها پر می‌شوند و می‌توانید قوانین خودتان را هم برایشان بنویسید. اگر تاریخچه را پاک کنید، این کالکشن‌ها حذف نمی‌شوند؛ چون یک «قاعدهٔ جستجو» همیشه ماندگارتر از جواب‌های آن لحظه است!

## پیست کردن هوشمند (Paste as...)

روی هر آیتم کلیدهای **⌥⏎** را بزنید تا قبل از رسیدن به مقصد، توسط مدل هوش مصنوعی پردازش شود. می‌توانید آن را به جدول Markdown، ترجمه، خلاصه، JSON یا کد Python تبدیل کنید.

خروجی به‌صورت تدریجی در یک پیش‌نمایش به شما نشان داده می‌شود و تا زمانی که آن را تأیید نکنید، چیزی پیست نمی‌شود. تبدیل متن در واقع حدس زدنِ نیت شماست؛ و اگر برنامه اشتباه حدس بزند و مستقیماً آن را در سند شما پیست کند، اعتمادتان را از دست می‌دهد.

*(نکته: برای آیتم‌هایی که به‌عنوان «رمز عبور» شناسایی شوند، نه تبدیلی در کار است، نه بسط معنایی و نه منوی هوش مصنوعی.)*

## رفتار با رمزهای عبور (مثل مواد رادیواکتیو!)

مدیر کلیپ‌بورد به تمام رمزهایی که کپی می‌کنید دسترسی دارد. Recall با این پیش‌فرض ساخته شده که این دسترسی یک خطر بزرگ است، نه یک ویژگی.

### شناسایی در لحظهٔ کپی
قبل از اینکه چیزی در دیسک نوشته شود، **۲۹ قانون مختلف** روی آن اجرا می‌شود. این قوانین بر اساس الگوهای ثابت و استاندارد هستند، بنابراین درصد خطای تشخیص (False Positive) نزدیک به صفر است:

| دسته‌بندی | مواردی که شناسایی می‌شوند |
| --- | --- |
| **کلاد و زیرساخت** | کلیدهای AWS (Access/Secret)، کلید API گوگل، توکن Cloudflare، کانفیگ Kubernetes |
| **پلتفرم‌های توسعه** | توکن‌های GitHub، GitLab، npm و Hugging Face |
| **پرداخت و ارتباطات** | کلید Stripe، شناسه Twilio، کلید SendGrid، توکن‌های Slack، ربات Discord و تلگرام |
| **هوش مصنوعی** | کلید APIهای Anthropic و کلیدهای عمومی `sk-` / `pk-` |
| **کلیدها و توکن‌ها** | کلیدهای خصوصی (Private Keys) و توکن‌های JWT |
| **اطلاعات شخصی** | شماره کارت بانکی، IBAN، کد ملی، کلمات بازیابی (Seed phrase)، رمز عبور برنامه‌ها |
| **الگوهای متنی** | URLهای حاوی پسورد، Connection String دیتابیس، فایل ENV، کدهای یک‌بارمصرف (OTP) |

اگر متنی با این الگوها مطابقت داشته باشد، برچسب `secret` می‌خورد. این آیتم **فقط در حافظه رم (RAM) می‌ماند و هرگز روی دیسک ذخیره نمی‌شود**، در لیست اصلی پنهان می‌شود، هوش مصنوعی روی آن اعمال نمی‌شود و در نهایت **پس از ۶۰ ثانیه (قابل تنظیم) به‌طور کامل پاک می‌شود**.

ریکال همچنین به شما می‌گوید کدام قانون باعث این تشخیص شده است؛ چون هشداری که نتوانید بررسی‌اش کنید، هشداری است که نهایتاً نادیده‌اش می‌گیرید. هر قانون را می‌توان به‌طور مستقل غیرفعال کرد.

### نادیده گرفتن برنامه‌های مدیریت رمز عبور
اگر چیزی را از **۲۸ برنامهٔ معروف مدیریت پسورد و احراز هویت** (مثل 1Password، Bitwarden، KeePassXC، Apple Passwords و Authy) کپی کنید، Recall اصلاً آن را نمی‌خواند. همچنین متونی که خود برنامه‌های مبدأ آن‌ها را مخفی (Concealed) علامت‌گذاری کرده باشند، نادیده گرفته می‌شوند. شما می‌توانید برنامه‌های دلخواه خود را هم به این لیست اضافه کنید.

### حالت فقط-حافظه (Memory-Only)
می‌توانید کل برنامه را طوری تنظیم کنید که فقط روی RAM اجرا شود. بدون دیتابیس، بدون پوشه دیتا و بدون کلید رمزنگاری. با بستن برنامه، همه‌چیز کاملاً پاک می‌شود.

### ذخیره‌سازی امن روی دیسک
بقیه اطلاعات در یک دیتابیس SQLiteِ رمزنگاری‌شده ذخیره می‌شوند: محتوا با الگوریتم AES-GCM قفل می‌شود، ایندکس‌های جستجو به‌صورت کور (Blind index) هستند، فایل ژورنال WAL امن است و پوشهٔ برنامه فقط دسترسی `0700` دارد.

## تولید کدهای تأیید دومرحله‌ای (2FA)

با فشردن **⌘⇧A**، نرم‌افزار Recall کدهای ۶ رقمی TOTP و HOTP تولید می‌کند (دقیقاً مثل یک برنامهٔ Authenticator).
اضافه کردن این قابلیت به یک کلیپ‌بورد منیجر می‌تواند ریسک بالایی داشته باشد، به همین دلیل معماری امنیتیِ آن کاملاً متفاوت از بقیه بخش‌های برنامه است.

### کلیدها در برنامه اصلی نیستند
کلید 2FA با رمز عبور فرق دارد. این کلید به‌صورت دائمی کدهای معتبر می‌سازد و خودش هرگز تغییر نمی‌کند. پس Recall آن را نگه نمی‌دارد.

این کلیدها در یک **پروسهٔ XPCِ کاملاً ایزوله (Sandboxed)** ذخیره می‌شوند که امضای دیجیتال، محیط بسته و پرمیشن‌های بسیار محدودِ خودش را دارد. برنامهٔ اصلی نمی‌تواند در محیط Sandbox باشد (چون خواندن کلیپ‌بورد و شبیه‌سازی کلید ⌘V نیاز به دسترسی‌های بالایی دارد)، اما **پروسهٔ کمکی کاملاً ایزوله است** و به هیچ‌چیز اضافه‌ای دسترسی ندارد: نه شبکه، نه فایل‌های سیستم، نه Accessibility، نه کلیپ‌بورد و نه دوربین.

پروتکل ارتباطی بین این دو بخش طوری است که هیچ متدی برای برگرداندن «کلید اصلی» وجود ندارد. برنامه فقط درخواستِ *کد* می‌کند و *کد* تحویل می‌گیرد.
کلیدها داخل محفظهٔ پروسهٔ کمکی با AES-GCM (با پرمیشن `0600`) و به‌صورت اتمیک (Atomic) روی یک سند واحد نوشته می‌شوند تا از خرابی داده‌ها جلوگیری شود.

### محافظت با Touch ID (به‌طور پیش‌فرض)
برای مشاهدهٔ کدها، احراز هویت **به‌طور پیش‌فرض الزامی است**. سه سیاست کلی وجود دارد:
* **همیشه:** برای هر کد، در هر بار استفاده.
* **با تایمر:** ۱، ۵، ۱۵، ۳۰ یا ۶۰ دقیقه. (تایمر فقط در رم نگه داشته می‌شود؛ با بستن برنامه، برای دسترسی مجدد باید دوباره احراز هویت کنید).
* **هرگز:** هر کسی که پشت کیبورد باشد می‌تواند کدها را ببیند.

این تنظیمات در خود پروسهٔ کمکی ذخیره می‌شود، نه در تنظیمات اصلی Recall.

### راه‌های افزودن حساب
* **اسکن QR کد از روی صفحه:** فقط کافیست محدودهٔ QR کد را روی صفحه مک خود انتخاب کنید تا Recall آن را بخواند. بدون نیاز به گوشی!
* **کپی کردن لینک `otpauth://`:** به محض کپی کردن، Recall به شما پیشنهاد می‌دهد آن را ذخیره کنید. (لینک‌های خروجیِ `otpauth-migration://` از Google Authenticator هم پشتیبانی می‌شوند).
* **وارد کردن دستی:** برای سایت‌هایی که فقط کد Base32 را به شما نشان می‌دهند.

### تنها کاری که انجام نمی‌دهد
ریکال **نمی‌تواند** کدهای 2FA را مستقیماً داخل فیلدهای پسورد در مک تایپ کند (Auto-fill). سیستم‌عامل macOS در این فیلدها قابلیت **Secure Event Input** را فعال می‌کند که دسترسیِ برنامه‌هایی مثل Recall را قطع می‌کند. این ویژگی دقیقاً برای محافظت از شما در برابر برنامه‌های شخص ثالث طراحی شده و Recall سعی نمی‌کند آن را دور بزند (و نباید هم بزند).

## اسنیپت‌ها و کدهای میانبر

می‌توانید به آیتم‌های خود یک کد میانبر (مثل `:sig` یا `:addr`) اختصاص دهید تا با تایپ کردنشان در هر محیطی، متن کامل جایگزین شود. یک Event tap (که فقط در حالت شنود است) منتظر کد می‌ماند، سپس آن را پاک کرده و اسنیپتِ شما را پیست می‌کند؛ و در نهایت هر چیزی که قبلاً روی کلیپ‌بوردتان بود را به آن برمی‌گرداند.

اگر آیتمی را پین کنید، برنامه با یک لینک ظریف (بدون باز کردن پاپ‌آپِ مزاحم) پیشنهاد می‌دهد که برای آن یک کد میانبر بسازید.

## استخراج متن از تصاویر (OCR)

با کلیدهای **⌘⇧⌥2** می‌توانید بخشی از صفحه را انتخاب کنید؛ موتور Vision متن داخل آن را می‌خواند و هم در کلیپ‌بورد و هم در تاریخچهٔ Recall می‌نشیند. مکانیزم انتخاب، همان ابزار آشنای `screencapture` مک است.

همچنین تمام تصاویری که کپی می‌کنید در پس‌زمینه OCR می‌شوند. در نتیجه، اگر از یک پیغام خطا اسکرین‌شات بگیرید، بعداً با سرچ کردن متنِ آن ارور، می‌توانید عکسش را پیدا کنید! تشخیص زبان هم کاملاً خودکار است.

## سایر امکانات

* **حفظ فرمت اصلی:** متن، RTF، عکس، فایل، لینک یا کدهای رنگ دقیقاً به همان شکل نمایش داده می‌شوند. (لینک‌ها با تایتل و آیکون، رنگ‌ها با یک پالت کوچک).
* **پین کردن:** موارد پین‌شده *هرگز* به‌طور خودکار (چه به دلیل پر شدن تاریخچه و چه انقضای زمان) حذف نمی‌شوند.
* **مقایسه دو آیتم (Diff):** با زدن ⌘D روی دو آیتم، تفاوت‌های آن‌ها را کلمه به کلمه ببینید (عالی برای مقایسه کانفیگ‌ها).
* **پیش‌نمایش سریع:** با زدن ⌘Y (دقیقاً مشابه پنجرهٔ Quick Look در مک).
* **صف پیست (Paste Queue):** با ⌘⌥⌃C آیتم‌ها را جمع کنید و به ترتیب پیست کنید.
* **تگ‌گذاری خودکار:** مدل هوش مصنوعیِ روی دستگاه، آیتم‌ها را تگ‌گذاری کرده و کالکشن‌های هوشمند را پر می‌کند.
* **برنامهٔ منوبار:** بدون آیکونِ مزاحم در Dock. هر وقت خواستید صدایش می‌کنید و بعد خودش کنار می‌رود.
* **پشتیبانی از زبان‌ها:** انگلیسی، فارسی (با چیدمان کامل راست‌به‌چپ)، روسی و چینی ساده‌شده.

## حریم خصوصی: هیچ‌چیز از مک شما خارج نمی‌شود

تمام فرآیندهای embedding، خلاصه‌سازی، تگ‌گذاری و تبدیل، **کاملاً محلی روی مک شما** اجرا می‌شوند. نیازی به اکانت نیست، هیچ تله‌متری و تحلیل دیتایی وجود ندارد و سینک ابری هم در کار نیست.

تنها استثنا، استخراجِ عنوان و آیکونِ لینک‌هایی است که کپی می‌کنید (که فقط یک ریکوئست مستقیم به همان سایت است و دیتا به جای دیگری نمی‌رود). در صورت تمایل می‌توانید این قابلیت را به‌طور کامل از تنظیمات خاموش کنید.

## نصب و راه‌اندازی

فعلاً باید برنامه را مستقیماً از روی سورس‌کد بیلد کنید. این کار با یک دستور ساده انجام می‌شود و به macOS 26 یا جدیدتر نیاز دارد (بدون نیاز به نصب وابستگی‌های شخص ثالث):

```bash
git clone https://github.com/cnazk/recall-mac.git
cd recall-mac
./Scripts/install.sh --build
```
این اسکریپت نسخهٔ قبلی را پاک کرده و برنامه را از نو کامپایل می‌کند (تا از تداخل فایل‌های قدیمی جلوگیری شود).

```bash
make test   # اجرای همهٔ تست‌ها
make app    # بیلد و ساین کردن برنامه در مسیر .build/Recall.app
make run    # بیلد و اجرای مستقیم برنامه
```

> **چرا فایل نصبی آماده (DMG) نداریم؟** > Recall فعلاً به‌صورت ad-hoc ساین شده است، چون پروژه هنوز عضو Apple Developer Program نیست. سیستم Gatekeeperِ مک، فایل‌های دانلودشده با این نوع امضا را مسدود می‌کند. راه‌حلِ رایج برای دور زدن این مشکل، خاموش کردن پرچم قرنطینه توسط کاربر است؛ اما این کار برای برنامه‌ای که به کلیپ‌بورد دسترسی دارد و اجازهٔ Accessibility می‌خواهد، اصلاً از نظر امنیتی توصیه نمی‌شود. در آپدیت‌های بعدی با گرفتن Developer ID این مشکل برطرف خواهد شد.

### محدودیت‌های شناخته‌شده

ترجیح می‌دهیم این موارد را همین ابتدا شفاف بگوییم؛ بعضی از آن‌ها در حال رفع هستند و بعضی دیگر خارج از کنترل ما:

| محدودیت | وضعیت فعلی |
| --- | --- |
| **نداشتن فایل نصبی (دانلود مستقیم)** | **در حال رفع.** دریافت Developer ID اپل در صف انجام است. |
| **از دست رفتن دسترسی Accessibility با هر آپدیت** | **با همان تغییر بالا رفع می‌شود.** امضای ثابت Developer ID مشکلِ تغییر هش بیلدها را حل می‌کند. |
| **پشتیبانی نکردن از OCR زبان فارسی** | **خارج از کنترل ماست.** موتور Vision اپل هنوز از زبان فارسی (fa) پشتیبانی نمی‌کند. البته تشخیص زبان خودکار روشن است و جستجوی کلمات فارسی در متونی که کپی می‌کنید بدون مشکل کار می‌کند. |
| **کار نکردن کدهای میانبر در فیلدهای پسورد** | **کاملاً عمدی و طبیعی است.** به خاطر ویژگی Secure Event Input در سیستم‌عامل macOS. Recall برای دور زدن امنیت سیستم‌عامل شما تلاشی نمی‌کند. |
